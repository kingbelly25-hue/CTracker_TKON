# 영어 미팅 대비 앱 — 1단계 기획서

> 세 번째 바이브코딩 프로젝트. "왜·뭘"까지 확정한 기획서.
> 화면 세부·데이터 스키마는 코딩하며 수렴(→ 방법론노트 6장 원칙).
> 원칙: 맞춤형(상용성 미고려) · 성과 가시화 중심 · 통암기 기반 · Gemini 무료 티어 활용.

---

## 1. 앱 정체성 (한 줄)

영어공부 앱이 아니라 **성과 가시화기 + 미팅 대비 블록 훈련기**다.
가르치는 게 목적이 아니라 **늘고 있음을 눈으로 보게 만드는 것**이 목적.

---

## 2. 사용자 데이터 (맞춤형 기준 — 설계의 뿌리)

- 50세, 대기업 부장, IR/파트너십 담당
- 영어 사용 간헐적·비절박 (외국 파트너 만날 때만 아쉬움)
- **다년간 시도→포기 반복. 원인 = 성과의 모호성 → 목적 회의 → 이탈**
- 통암기가 유일하게 효과를 본 방법 (셀 수 있어서 성과가 잡힘)
- 실전 경험: 블랙록 아태·노션 글로벌 세일즈 미팅
  → "핵심 질문을 짧게 잘 듣기 + 정형 발표를 잘 하기"가 필요하다고 체감
- **1호 미팅 = 노션 글로벌 파트너십 (3개월 내, 날짜 미정, 협력방안 논의)**

### 핵심 급소 (앱이 막아야 할 단 하나)

> **성과 모호 → 목적 회의 → 포기.**
> 모든 화면이 **셀 수 있는 진전**을 보여야 한다.

(업계 용어 "plateau of despair" — 노력해도 안 는다고 느끼는 정체기가 이탈의 정체)

---

## 3. 두 축 + 콘텐츠 성격

파트너십 협의는 **통짜 대본이 안 통한다** (상대 반응에 따라 흐름이 바뀜).
→ 통짜가 아니라 **레고 블록**을 통암기하고 현장에서 조립한다.

- **송신축** — 정형 블록 인출 훈련
  - 오프닝(회사·목적 1~2분), 핵심 메시지 블록(줄 것/원할 것),
    Q&A 답변, 연결 표현("That's a good point, and…")
- **수신축** — 빈출 질문 패턴 청취
  - IR/세일즈 미팅 질문은 패턴이 정해짐. 반복 청취로 귀 익히기.

---

## 4. 4개 화면

1. **미팅** — 대비 중인 미팅 단위로 묶음 (1호=노션). 미팅별 블록·질문·준비도가 담김
2. **송신 훈련** — 한글 트리거 → 영어 블록 인출 → 판정 → 간격 반복(SRS)
3. **수신 훈련** — 질문 음원 듣기 → 알아들었나 확인
4. **성과** — 세 겹 가시화 (5장)

---

## 5. 성과 화면 — 이 앱의 심장 (세 겹 가시화)

급소가 성과 모호이므로 성과를 세 겹으로 입체화한다.

### ① 정성·내부 — Before/After 자기 녹음 대조 【1단계 핵심】
- 시작 시 영어 발화 녹음 → 2주 뒤 같은 문장 재녹음 → 나란히 재생.
- 과거의 버벅임과 현재를 귀로 직접 비교 = 성과가 "느낌"이 아니라 **증거**.
- 다른 앱이 못 하는 부분. 성과 모호를 정면으로 때림.

### ② 정량·내부 — 미팅 준비도 % + 인출 곡선
- 개별 개수 대신 "지금 노션 미팅 들어가면 몇 % 준비?"를 **단일 숫자**로.
- 블록별 인출 성공 가중합산 → "노션 준비도 62%". 목표 직결로 진도가 보임.
- 인출 곡선: 같은 블록 성공률이 시간 두고 오르는 그래프 = 통암기 정착 시각화.

### ③ 정량·외부 — 오픽/토스 점수 마일스톤 (중간 검증 이벤트)
- 시험을 앱 축으로 넣지 않음. 3개월 여정 중간에 한 번 응시.
- 점수를 **외부 인증 마일스톤**으로 박음. 앱이 시험을 가르치는 게 아니라
  훈련 결과를 시험으로 **검증**.
- 한계: 응시료 별도(앱 요금 아님).

---

## 6. API 설계 (Gemini 무료 티어)

무료 티어(Flash 계열)로 아래 다 가능 — 검색 확인(2026.7):

- **인출 판정**: 한글 트리거 → 영어 입력 → LLM이 의미·자연스러움 판정+교정
- **모의 Q&A(블록 조립 훈련)**: LLM에 노션 파트너십 임원 역할 →
  질문 던지고 네 블록 답변에 반응. "미팅 지나면 빈 그릇" + "조립 훈련 없음" 동시 해결
- **음성**: STT(말한 것 판정)·TTS(듣기 음원) 무료 티어 가능.
  Gemini 3 Flash 무료 = 분당 10요청·하루 1,500요청(개인 1명 넉넉)

### 결정적 급소 — 프라이버시 (반드시 명시)

무료 티어는 **입력이 구글 학습에 쓰일 수 있음.**
IR/파트너십 대본은 회사 기밀에 닿을 수 있어 체중 데이터보다 민감.

**→ 이분법이 아니라 "민감도 농도 관리":**

- **범용 연습 (API 마음껏)**: 회사명·수치·전략을 뺀 표현.
  "우리 회사는 B2B SaaS다" → "우리 회사는 [업종]이다" 식 **자리표시자** 처리.
  뉘앙스는 남되 식별정보는 뺌.
- **실전 대본 (API 격리, 텍스트만)**: 노션·실제 수치·구체 전략이 박힌 것.

핵심: 뉘앙스가 남는 걸 막으려 하지 말고, **"식별 가능한 기밀"만 뺀다.**
뉘앙스(파트너십 성격)는 남아도 기밀 아님. 위험한 건 "노션과 무슨 조건으로 뭘 한다"는 구체값.

**분류 책임은 100% 사용자.** 앱은 칸만 나눠줄 뿐 기밀을 자동 감지 못 함.
CutTracker "사진 로컬만"과 달리 코드 강제가 아닌 **규율.** 이 위험은 인지한 채 지고 감.

## 7. 기술 경로

**배관 재활용 = 이식 방식 (복제 아님)**

- CutTracker의 동기화(연결 코드+Firestore)·배포(Vercel)·저장 계층을
  **빈 새 프로젝트에 손으로 다시 연결.**
- 이유: 단순 복제는 "연결 경험"이 안 남아 학습에 후퇴.
  이식은 "이미 아는 배관을 다른 몸통에 새로 꽂는" 경험 → 바이브코딩 학습 목적에 맞음.
- 화면 4개는 새로 작성.

**녹음 저장 = C방식 (localStorage → 커지면 IndexedDB)**

- 녹음은 **로컬 전용** — Firestore 동기화 안 함 (사진과 같은 처리, 1MiB 우회).
- 즉 Before/After 대조는 **같은 기기에서만** 재생됨 (다른 기기엔 안 넘어감).
- 1단계: localStorage(미팅당 Before/After 2개 제한, base64).
- localStorage는 잘 지워짐(캐시청소·사파리 7일 등) → 성과 증거 소실 위험 인지.
  용량 차면 IndexedDB로 이전이 근본 해결(저장 계층만 교체, 앱 본체 불변).

## 8. 1단계 / 나중 경계 (과설계 방지)

### 1단계 (지금)
- [ ] 미팅 화면: 미팅 단위 묶음 (1호=노션)
- [ ] 송신 훈련: 한글→영어 블록 인출 + SRS
- [ ] 수신 훈련: 질문 음원 청취 (무료 TTS)
- [ ] 성과 화면 — Before/After 자기 녹음 대조 【핵심 급소 장치】
- [ ] 성과 화면 — 미팅 준비도 %
- [ ] 녹음 저장: localStorage 시작 (2개 제한) → 용량 시 IndexedDB
- [ ] 콘텐츠 2종 분리 구조 (연습용/실전 플래그, 자리표시자)
- [ ] 배관 이식 (동기화·배포)
- [ ] **시작 콘텐츠 = 연습용 범용** (노션 실전은 텍스트 저장만, API 격리)

### 나중 (효과 보고 확장)
- 녹음 저장소 IndexedDB 이전 (용량 실측 후)
- 모의 Q&A (LLM 상대역)
- 음성 판정(STT)
- 오픽/토스 마일스톤
- 인출 곡선 그래프

(CutTracker 사양·콘텐츠 분리 방식 따름). 기획서엔 구조만, 실제 콘텐츠는 별도.
