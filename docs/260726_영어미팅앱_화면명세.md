# 화면 기능 명세

> 기획서(`영어미팅앱_기획서_1단계.md`) 8장이 가리키는 화면 상세 문서.
> 기획서는 "왜·뭘"(안 바뀜), 이 문서는 "어떻게"(코딩하며 계속 갱신됨) — 성격이 달라 분리.
> 각 항목에 결정 근거(왜 이렇게 했는지)를 남겨, 나중에 재논의 시 왜곡 방지.

---

## 0. 데이터 관계 뼈대 (필드·타입은 코딩하며 수렴)

```
미팅 (1개, 1단계=노션 고정)
 ├─ 블록 (여러 개, 송신훈련용 — 오프닝/핵심메시지 등 카테고리)
 │   └─ 학습이력 (인출 성공/실패 누적, SRS 간격 계산용)
 ├─ 질문 (여러 개, 수신훈련용 — 빈출 질문 패턴)
 │   └─ 청취이력 (이해도 3단계 판정 누적, SRS 간격 계산용)
 ├─ 준비도% (블록+질문 학습이력에서 계산)
 └─ Before/After 녹음 (최대 2개, 로컬 저장, localStorage)
```

---

## 1. 미팅 화면

### 1-1. 미팅 목록
| 기능 | 설명 |
|---|---|
| 목록 표시 | 미팅 카드 나열 (1단계=1개, 노션) |
| 준비도% 표시 | 카드 안에 진행률 바로 표시 |
| 선택 | 카드 클릭 → 미팅 상세로 이동 |
| 새 미팅 추가 | **보류 — 4화면 전체 확정 후 마지막에 설계** |

### 1-2. 미팅 상세
| 기능 | 설명 |
|---|---|
| 준비도% | 상단 고정 표시 |
| 오늘 복습 시작 (말하기) | SRS가 고른 밀린 블록 수 표시 → 눌러서 송신훈련 진입 |
| 오늘 복습 시작 (듣기) | SRS가 고른 밀린 질문 수 표시 → 눌러서 수신훈련 진입 |
| 카테고리별 복습 예정 수 | 총 개수 아님, "복습 N개"만 (근거: 아래 3번) |

**결정 근거**:
1. 말하기/듣기는 인지 자원이 달라 전환비용 발생 → 시작 버튼 분리 (말하기=강조색, 듣기=보조색. 기획서 3장·사용자 실전경험담에서 말하기가 먼저 언급된 순서 반영)
2. 카테고리 클릭 시 블록 목록을 펼쳐 고르게 하지 않음 — 목록 브라우징은 재인(recognition)이지 인출(recall)이 아니라서 SRS 효과를 깎아먹음. 대신 "시작" 버튼 하나로 SRS가 카테고리 섞어서(interleaved) 자동 제시 → 실전 조립력(레고 블록 조립, 기획서 3장) 훈련에 유리
3. 총 개수 대신 "복습 예정 N개"만 노출 — 총량 표시는 압박감만 주고 진전감을 안 줌 (급소: 성과 모호 방지)

## 2. 송신 훈련 화면

| 단계 | 기능 | 설명 |
|---|---|---|
| 1 | 트리거 제시 | 한글 트리거 (SRS가 고름, 카테고리 섞임). 세션 내 진행상황(N/M) 상단 표시 |
| 2 | 입력 | 텍스트 타이핑 (1단계=음성 아님, STT는 8장 "나중" 항목) |
| 3 | 판정 중 | LLM 호출 대기, 입력값 유지 표시 |
| 4 | 판정 결과 | 성공/보완 판정 + 정답 예시 + (선택) "이 판정이 이상한가요?" 텍스트 링크 |
| 5 | SRS 갱신 | 판정 결과로 다음 복습 간격 자동 계산 |

**결정 근거**:
- 정답은 입력 후에만 노출 (desirable difficulty — 인출 효과는 애써서 기억해내는 데서 나옴, 힌트 선노출 시 재인으로 전락)
- **판정 기준: 의미가 통하면 격식 수준(formal/casual) 무관하게 성공 처리.** 격식 차이는 참고 코멘트로만 덧붙임 (LLM 프롬프트 지침에 반영 필요 — 기획서 6장 API 설계에 추가할 것)
- "동의/이의" 두 버튼 방식 폐기 — 자가판정은 애초에 이의를 낼 근거가 없어 실효성 없음. 대신 LLM 프롬프트 자체를 정교화하는 쪽으로 문제를 옮김
- 가벼운 "이상해요" 링크만 유지 — 판정 오류 사례 기록용, 즉시 재판정 기능 아님 (콘텐츠·프롬프트 보정은 8장 "나중" 항목)
- 판정 실패/지연 대비 필요 (무료 티어 특성, 기획서 6장) — "판정 중" 화면에 임계값 넘으면 "건너뛰고 나중에 판정" 옵션 노출. **정확한 대기 초수·재시도 방식은 코딩하며 수렴**

## 3. 수신 훈련 화면

| 단계 | 기능 | 설명 |
|---|---|---|
| 1 | 음원 재생 | TTS, 다시 듣기 **무제한** (초반 좌절 방지 우선, 횟수 제한은 8장/버전업 후보로 이동) |
| 2 | 요지 입력 | 전체 받아쓰기 아님 — "핵심만 한 줄, 한국어 가능" |
| 3 | 판정 중 | LLM 호출 대기 |
| 4 | 판정 결과 | 3단계 판정 (완전 파악 / 일부만 파악 / 놓침) + 놓친 부분 구체 설명 + 원문 전체 공개 |

**결정 근거**:
- 자가판정(알아들었다/못 알아들었다 버튼)만으론 SRS 연계 근거 부족 → "요지 말하기(gist recall)"로 절충. 받아쓰기(dictation)는 듣기+쓰기 이중과제라 배제
- 판정은 이분법 아닌 **3단계** — 실제 청취 이해가 이분법이 아니므로 (부분 이해를 정확히 SRS에 반영해야 복습 스케줄이 맞음)
- 원문 전체 공개 — 판정 근거를 사용자가 직접 확인해야 신뢰 형성. 실전 감각(원문을 눈으로 볼 일 없음)과는 다소 괴리 있음을 인지하고 감수 (1단계는 학습 목적 우선)

## 4. 성과 화면

구조 순서 (콜드스타트 문제 대응 — 2주간 Before/After가 나오기 전까지 빈 화면 방지):

| 순서 | 블록 | 설명 |
|---|---|---|
| 1 | 준비도% (히어로) | 최상단 큰 숫자. "지난주보다 +N%" 변화량 표시. **첫 주(비교 데이터 없음)엔 이 줄 숨기고 "오늘 첫 기록"으로 대체** |
| 2 | 인출 성공률 추이 | 단순 추세선 (스파크라인 수준, 축·범례 없음) |
| 3 | Before/After 녹음 | 2주간 잠금(locked) 상태, "D-N일 후 공개" 카운트다운 + "시작 녹음은 저장돼 있어요" 안심 문구 |

**결정 근거**:
- 매일 갱신되는 지표(준비도%)를 최상단에 둬서 습관 형성의 즉각 보상 고리를 만듦
- Before/After를 처음부터 공개하지 않고 잠금+카운트다운 — (a) 초반 이탈 방지용 기대감 형성 (b) 공개 순간의 임팩트 보존
- 추가 지표(총 학습시간·연속일수 등)는 1단계에서 배제 — 통계 과부하가 새로운 형태의 성과 모호를 유발할 위험 (버전업 후보로 이동)
